# 历史开发草案 · 确认实验规范

> 本文件记录 2026 年 10 月的八题原型。最终交付采用 R01–R06 六题及 G/E 两组，复现入口见[提交包说明](../README.md)。如需检查旧原型，请使用 `python3 -m curve_audit legacy --help`。

版本 `curve-confirmation-20261015.1`。以下内容保留原型当时的设计和状态，以便回查。

## 1. 研究问题与实验单位

在相同题目、限定证据及允许资源下，独立计算和独立取数分别带来何种变化？主要评价正确可答覆盖、已经报告的错误、遗漏、拒答和审核伤害，分别统计，不把补齐缺值直接写成纠正错误数值。

每题每次重复只生成一份公共初稿，再分为以下三个审核条件：

| 条件 | 审核路径 | 主要比较 |
|---|---|---|
| `self_review` | 模型自行复查 | 基准 |
| `archive_recompute` | 独立实现读取同一档案、重算 | 对比自审，检查计算反馈的增益 |
| `source_recompute` | 自行定位区块、另源取数、独立计算 | 对比同档案重算，检查取数路径的增益 |

计划为 8 题 × 3 次重复 × 3 条件，共 **72 份模型终稿**、24 份共享初稿和 8 份固定参考输出。正式实验保存全部计划输出、失败和资源消耗；失败不得以静默重跑的成功结果替换。共享初稿实验主要回答审核阶段的作用，不能自动代表端到端系统表现。

## 2. 小题集草案：8 题、26 个组件

| 任务族 | 题号 | 每题组件数 | 内容 |
|---|---|---:|---|
| 单点与单位 | C01–C02 | 3 | DAI 占比、USDC 占比、1000 输入 USDC→USDT 报价；审核原始整数到归一化的单位关系 |
| 窗口与规模 | C03–C04 | 3 | USDC 占比末减初变化、100000 输入报价、规模敏感度的采样最大值 |
| 先定位再查询 | C05–C06 | 4 | 采样失衡最大值；取得真实返回时点后查询前一小时、该小时、后一小时报价 |
| 局部缺失与边界 | C07–C08 | 3 | 保留首点占比；拒答缺样的完整窗口变化；拒答小时采样无法确定的连续时间真实峰值 |

草案共有 22 个可答组件、4 个需要合理拒答的组件。默认使用原事件的两个短窗口：2023-03-10 00:00–06:00 UTC、2023-03-11 00:00–06:00 UTC。该默认设置明确属于**单事件草案**。第二事件尚未选定，不能声称跨事件泛化；必须先检查历史接口可用性，并与用户提供的真人记录对齐，再冻结正式题集。

动态查询在公共题目中仅出现 `time_from_slot: S1` 和小时偏移。实际峰值时点与 `resolved_query` 留在私有参考包，审核执行器必须根据先前真实返回值展开查询。允许证据还包括前后小时查询所需的 1 小时边界扩展。局部缺失题明确排除窗口第三小时的样本，所有条件均不得从其他接口补回被题目排除的数据。

## 3. 统一判定规范

公开规范由 `curve_audit.confirmation` 和 `config/confirmation_protocol.json` 记录。评分器与验证器共享该判定规范；金融计算实现与参考答案不共享。

- 派生小数采用绝对容差 `1e-8`、相对容差 0；只接受有限数字，拒绝 NaN、无穷和布尔值。
- 原始整数必须为规范十进制非负整数字符串，精确匹配；不使用浮点或派生值容差。
- 单位、币种、方向、输入规模、目标时间、区块标识精确匹配；单位注释不自动剥离，也不隐式更换报价方向。
- 已报告数值主张的有效状态为 `supported` 或 `conflicting`。
- 拒答状态为 `unsupported` 或 `refused`；理由可在主张解释、主张拒答字段、报告拒答字段或正文。自动程序只检查理由存在，语义是否充分须另行审核。
- 同一组件同时出现正确数值与错误数值，或同时断言数值并拒答，不能凭其中一条正确记录取得完整覆盖。
- 接口超时、历史状态不可用、来源冲突和无效 RPC 响应归为 `unverifiable`，不能直接归因于 Agent 错误。

## 4. 真人标准答案记录与冻结门禁

该草案阶段的人审门禁状态为 `pending_external_records`。

`write_reference_review_package(directory, tasks, candidates)` 生成私有候选参考、公开题目、A/B 空表和仲裁空表。若准备写入的任一文件已存在，程序拒绝覆盖，以保护后续填写或导入的真人记录。

每个候选参考至少包含 `task_id`、`slot_id`、`answerable`，可答组件包含数值和单位。支持将计算结果放在 `result` 内。建议保留以下结构：

```json
{
  "task_id": "C05",
  "slot_id": "S2",
  "answerable": true,
  "query": {"metric": "quote_rate", "operation": "last", "direction": "USDC_USDT", "size": 100000, "time_from_slot": "S1", "offset_hours": -1},
  "resolved_query": {"metric": "quote_rate", "operation": "last", "direction": "USDC_USDT", "size": 100000, "start": "由真实定位结果确定", "end": "由真实定位结果确定"},
  "result": {"value": "待计算与人工核对", "unit": "USDT/USDC"}
}
```

上例是字段说明，包含占位值，**不可作为已验证参考答案**。

真人记录采用独立 A/B 记录，每份具有 `reviewer_id`、`reviewer_type: human`、`independent_review: true`、`review_package_sha256` 和完整 `slots`。每个槽位记录：

- `task_id`、`slot_id`、候选 `reference_sha256`、真实核对 UTC 时间；
- `verdict: approve`，或 `revise` 并提供 `proposed_reference`；
- 非空 `raw_record_refs` 与 `calculation_note`；
- `checked_fields`：至少核对 answerability、evidence_boundary；可答项另需 value、unit、time、block、formula、raw_evidence、raw_to_normalized。

A/B 必须是不同核对者。存在分歧时，第三位不同真人提供绑定同一包的仲裁记录，逐项填写 `resolved_reference`、真实时间和 `resolution_note`。无分歧时无需虚构仲裁。

`validate_reference_review` 检查包与候选哈希、完整覆盖、不同核对者、核对字段及分歧处理，通过后返回含记录哈希的 `frozen_reference` 和 `frozen_reference_sha256`。这只能验证所提供记录的完整性与绑定关系，不能由程序证明真人身份及实际独立性。导入者须保留原始外部记录及其文件校验值，准确说明来源。

正式实验门禁 `require_formal_ready` 同时要求：

1. 真人记录已验证，冻结参考哈希正确；
2. 题集已冻结，题集哈希与参考包一致；
3. 独立取数路径通过检查；
4. 三条件相同的总 token 上限已由适配器强制执行。

仅记录实际 token 或给出提示词预算，不能满足第 4 项。现有 CLI 尚不能强制总 token 预算，状态保持 `pending_hard_cap_adapter`。具体上限须通过独立开发题检查、在正式运行前冻结，并计入初稿、反馈和终稿；RPC 与独立验证计算的耗时、请求数和费用另外记录。

## 5. 自动评价范围及分母

`score_report(report, references)` 每次只评价一题，主张通过 `slot_id` 关联所需组件。自动范围为 `report.claims`，不等于自由正文事实准确率。

| 指标 | 分子 | 分母 |
|---|---|---|
| 正确可答覆盖 | 全部匹配数值正确、无矛盾拒答的可答组件 | 全部要求可答组件 |
| 已报告数值错误率 | 数值本身超容差或无效的已报告主张 | 全部已报告数值主张 |
| 单位／区块／时间／对象错误率 | 对应维度不匹配的已报告主张 | 全部已报告数值主张 |
| 遗漏率 | 没有数值断言且没有明确拒答的可答组件 | 全部要求可答组件 |
| 过度拒答率 | 对可答组件明确拒答且没有数值断言 | 全部要求可答组件 |
| 合理拒答率 | 无数值编造、明确拒答且有理由的不可答组件 | 全部要求不可答组件 |
| 无依据结构化主张率 | 对不可答组件断言数值、超出封闭参考范围或状态不被接受的数值主张 | 全部已报告数值主张 |

没有任何已报告数值时，相应错误率为 `null`，不能写成零错误。超出参考范围的数值会标为未裁定／无依据，不能自动声称其在现实世界为假。失败输出仍保留在要求组件的覆盖分母中；执行失败另列，不从计划数量消失。每个指标输出明确分子、分母、值和适用范围。

`score_repair(initial, final, references)` 分开统计已报告错误纠正、遗漏补齐、过度拒答恢复、正确答案损失及新增已报告错误。正文幻觉变化不由这些指标推断。

## 6. 验证器场景：32 个预先规定的场景

- 12 个已知错误：数值上调／下调、货币单位／方向单位、区块号／区块哈希、窗口错位／缺采样、方向颠倒／输入规模改变、余额档案／报价档案自洽篡改。
- 12 个逐一匹配的干净对照。
- 4 个合法拒答：内部缺样、被排除的报价时点、允许窗口为空、连续峰值不可识别。
- 4 个来源未知：超时、历史状态不可用、来源冲突、无效响应。

`build_fault_scenarios()` 当前输出**场景规范**，状态 `specification_not_executed`，不得当作测试执行结果。`classify_verifier_scenario()` 要求检出与实际注入问题一致；指出另一个问题不算正确检出。干净样例误报与来源未知分开统计，来源失败不能计作 Agent 错误。

## 7. 交付边界

当前工程可完成规范、草案、独立取数与重算接口、预算门禁及自动规则测试。真人原始记录、正式题集冻结、真实强制预算和正式模型执行必须如实标注实际状态。旧实验不会混入本轮统计。研究结论限定在实际事件、题集和可验证的结构化输出范围，不预先保证某一审核条件更优。
